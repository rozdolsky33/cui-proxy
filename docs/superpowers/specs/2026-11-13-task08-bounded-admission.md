# Task 08: bounded admission and text fairness

## Intent and evidence
Task 04 left concurrency and fairness unqualified; Task 07 reduced detector CPU but does not bound offered work. The four-agent contract budgets 512 MiB proxy RSS and 1 GiB child RSS. Today bodies are read without process-wide admission, and two extraction helper slots have an unbounded wait population. Normal requests reach 1 MiB; stress requests reach 8 MiB. Keep four normal clients useful while bounding overload before body allocation.

## Chosen approach
Use process-wide request admission before metadata scanning/body reads, and a separate bounded helper queue. A single FIFO would let a large reservation at its head block lightweight requests; separate small/bulk FIFO lanes reserve capacity for small work while alternating eligible lanes. Rejecting every contended request would avoid a queue but penalize ordinary short bursts. These choices are implementation judgments under standing autonomous authorization.

Request defaults: eight active requests, eight queued requests, 64 MiB reserved input bytes, five-second maximum queue wait. Small means a bounded body of at most 2 MiB. Bulk requests may occupy at most six active slots and 56 MiB, leaving two slots and 8 MiB available for small requests. Small work may borrow unused general capacity. Alternate eligible lane heads to avoid starvation; FIFO within a lane. Limits apply across proxy handlers. Hold the reservation through response completion so long streams remain bounded. No per-client identity or supplied label is trusted.

Reserve declared Content-Length, or the policy body limit when unknown. Clamp body reading to the reservation as well as the policy limit so false length declarations cannot exceed admission accounting. Reject declared lengths above the policy limit as existing 413. Requests whose reservation can never fit receive an immediate overload response. A zero-length request consumes a slot. The 64 MiB input cap is an estimate, not a Go heap/RSS hard limit: a fourfold working-copy allowance is 256 MiB, leaving budget for mappings, runtime and other state. Measure actual RSS; do not claim the reservation proves the RSS contract. Unknown-length large requests are conservatively bulk.

Helper defaults: retain two active processes, allow only two waiters, retain the existing 30-second per-request extraction deadline. All queue acquisition and release is cancellation-safe; abandoned or timed-out waiters cannot retain slots. Busy extraction still returns its existing closed attachment diagnostic; generic admission returns HTTP 503, code overload, Retry-After: 1 and backoff guidance. Neither can enter the configured sanitization passthrough path. Audit and metrics remain value-free.

## Verification and limits
Test exact active/queued/byte bounds, FIFO and cross-lane progress, cancellation/grant races, idempotent release and impossible weights. HTTP tests must prove refusal before body reads, zero upstream calls even under passthrough, cancellation drain, strict body-length accounting, and small-request progress while bulk capacity is occupied. Helper tests prove two active/two queued and prompt removal. Expose admission active/queued/reserved-byte gauges plus a closed admission_wait stage.

Use deterministic mixed traffic (three attachment-heavy clients, one normal text client) to measure p95/p99 added delay at the three normal sizes and preserve all outcomes. A bounded experiment is not Task 11 sustained qualification. Record whether the 150 ms p95/500 ms p99 target passes; do not weaken it or claim a failed target passed. Run the existing HTTP semantic/policy corpus, race tests, Python workflow tests, vet, staticcheck and required CI. No caching, detector rewrite, new configuration knobs or client-identity scheduler in this task.
