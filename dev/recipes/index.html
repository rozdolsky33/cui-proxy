    Configuration recipes¶

    Choose the behavior you need, download a complete YAML file, and put the dictionary beside it. These examples use invented names. Review the rules for your environment before relying on them.

    Goal Configuration Dictionary files What a match does
    Mask common values and your service names sanitize.yaml hosts.txt Replace and restore
    Mask selected OCI/AWS CLI configuration assignments cloud-cli.yaml hosts.txt Replace and restore; coverage and limits
    Refuse any detected value strict.yaml hosts.txt Block the entire request
    Mask ordinary values, block restricted categories selective-block.yaml hosts.txt, restricted-names.txt Per-rule behavior
    Extract PDF/image text before masking (from v0.4.0) attachment-text.yaml hosts.txt Replace files with extracted text, then sanitize matches
    Keep mappings across restarts persistent-vault.yaml hosts.txt Replace and restore using an encrypted file vault
    Learn on separate ports tutorial.yaml hosts.txt Mask on ports 18787 / 18788

    Download and validate a recipe¶

    This creates a private new directory and does not replace your running config:

    cui_recipe_dir=$(mktemp -d "${TMPDIR:-/tmp}/cui-recipe.XXXXXX")
curl -fsSL https://rozdolsky33.github.io/cui-proxy/examples/sanitize.yaml \
  -o "$cui_recipe_dir/config.yaml"
curl -fsSL https://rozdolsky33.github.io/cui-proxy/examples/hosts.txt \
  -o "$cui_recipe_dir/hosts.txt"
chmod 600 "$cui_recipe_dir/config.yaml" "$cui_recipe_dir/hosts.txt"
cui-proxy check-config -config "$cui_recipe_dir/config.yaml"
printf '%s\n' 'Check db.demo.example for DEMO-123456' |
  cui-proxy test-rules -config "$cui_recipe_dir/config.yaml"

    For another recipe, change the downloaded YAML filename and fetch any additional dictionary in the table. Relative paths resolve against the YAML's directory, regardless of the current terminal directory. YAML does not expand ~ or environment variables and does not merge multiple files.

    All recipes except the tutorial use the normal ports. Stop an existing proxy before serving one, or give it unique listener ports, vault files and audit files. check-config and test-rules do not start a listener. For a permanent setup, move the reviewed files to a private directory you intend to keep and explicitly select that YAML with serve -config or the menu-bar installer.

    All recipes enable audit and set audit.on_error: block. The generated cui-proxy init starter instead defaults to warning on an audit-write failure under sanitize. This choice is explicit so a recipe cannot silently forward a request without its decision record.

    Local PDF/image text extraction (from v0.4.0)¶

    This requires the v0.4.0 or newer plus local extraction tools. Read attachment inspection before enabling it. Original files and filenames are dropped; only extracted text is inspected and forwarded. Strict or explicit block rules still apply to that text. All conversion-mode failures block.

    attachment-text.yaml — complete configuration
    # Complete configuration for attachment support in v0.4.0 or newer.
# Requires local Poppler/Tesseract; save hosts.txt beside this file.
listen: localhost:8787
ui:
  listen: localhost:8788
upstreams:
  codex: https://chatgpt.com/backend-api/codex
policy:
  profile: sanitize
  on_error: block
  unsupported: block
  attachments: extract_text
  max_body_bytes: 20971520
vault:
  mode: memory
audit:
  enabled: true
  file: .state/attachment-decisions.jsonl
  on_error: block
rules:
  - name: builtin
    type: builtin
  - name: service-hosts
    type: dictionary
    file: hosts.txt
    synth: hostname
  - name: aws-keys
    type: regex
    pattern: '\b(?:AKIA|ASIA)[0-9A-Z]{16}\b'
    synth: secret
  - name: ticket-ids
    type: regex
    pattern: '\bDEMO-[0-9]{6}\b'
    synth: secret

    Everyday masking¶

    Use this when detected values may be represented by stand-ins. It enables the built-in bundle, service names, an extra AWS-key regex, and a fictional ticket pattern. A type: builtin rule is required to enable the bundle; it is not automatically added to arbitrary YAML.

    sanitize.yaml — complete file
    # Complete configuration. Save hosts.txt beside this file.
listen: localhost:8787
ui:
  listen: localhost:8788
upstreams:
  codex: https://chatgpt.com/backend-api/codex
policy:
  profile: sanitize
  on_error: block
  unsupported: block
  max_body_bytes: 20971520
vault:
  mode: memory
audit:
  enabled: true
  file: .state/sanitize-decisions.jsonl
  on_error: block
rules:
  - name: builtin
    type: builtin
  - name: service-hosts
    type: dictionary
    file: hosts.txt
    synth: hostname
  - name: aws-keys
    type: regex
    pattern: '\b(?:AKIA|ASIA)[0-9A-Z]{16}\b'
    synth: secret
  - name: ticket-ids
    type: regex
    pattern: '\bDEMO-[0-9]{6}\b'
    synth: secret
    hosts.txt
    # Fabricated demonstration entries. Replace/add names for your own environment.
# One literal per line; blank lines and whole-line comments are ignored.
db.demo.example
build.demo.example

    Expected previews:

    Input Result
    db.demo.example Synthetic .example hostname; service-hosts match
    203.0.113.42 Different address; builtin.ipv4 match
    DEMO-123456 Opaque stand-in; ticket-ids match
    DEMO-12345 Unchanged: does not have six digits
    Explain a retry loop Unchanged: no matching value

    Strict: refuse every detection¶

    Use strict when your policy requires a request containing any detected value to be refused. The whole request is blocked; the proxy does not send a redacted version. Strict also broadens checks on protocol identifiers. Unrecognized sensitive content is still outside pattern-based detection.

    strict.yaml — complete file
    # Complete configuration. Save hosts.txt beside this file.
listen: localhost:8787
ui:
  listen: localhost:8788
upstreams:
  codex: https://chatgpt.com/backend-api/codex
policy:
  profile: strict
  on_error: block
  unsupported: block
vault:
  mode: memory
audit:
  enabled: true
  file: .state/strict-decisions.jsonl
  on_error: block
rules:
  - name: builtin
    type: builtin
  - name: service-hosts
    type: dictionary
    file: hosts.txt
    synth: hostname
  - name: aws-keys
    type: regex
    pattern: '\b(?:AKIA|ASIA)[0-9A-Z]{16}\b'
    synth: secret
  - name: ticket-ids
    type: regex
    pattern: '\bDEMO-[0-9]{6}\b'
    synth: secret

    Run the same test-rules examples with this file. A host, address or ticket match returns an error and exit code 1. A clean phrase succeeds unchanged. policy check -require-strict -config PATH verifies the profile is strict.

    Strict requires at least one rule, policy.on_error: block, enabled audit, and blocking audit-write failures. Do not add action: sanitize; it is invalid under strict. See Policy profiles.

    Mask most values, block selected rules¶

    Use sanitize at the top level and explicit action: block on the categories you must refuse. This example masks service names and ticket IDs but blocks a restricted name or an AWS access-key-shaped value.

    selective-block.yaml — complete file
    # Complete configuration. Save both dictionary files beside this file.
listen: localhost:8787
ui:
  listen: localhost:8788
upstreams:
  codex: https://chatgpt.com/backend-api/codex
policy:
  profile: sanitize
  on_error: block
  unsupported: block
vault:
  mode: memory
audit:
  enabled: true
  file: .state/selective-decisions.jsonl
  on_error: block
rules:
  - name: builtin
    type: builtin
  - name: service-hosts
    type: dictionary
    file: hosts.txt
    synth: hostname
  - name: restricted-names
    type: dictionary
    file: restricted-names.txt
    synth: secret
    action: block
  - name: aws-keys
    type: regex
    pattern: '\b(?:AKIA|ASIA)[0-9A-Z]{16}\b'
    synth: secret
    action: block
  - name: ticket-ids
    type: regex
    pattern: '\bDEMO-[0-9]{6}\b'
    synth: secret
    restricted-names.txt
    # Fabricated name used to demonstrate an explicit blocking rule.
restricted-demo-project

    db.demo.example is masked; restricted-demo-project blocks. If one request contains both, the entire request blocks. A blocking rule wins even when its match overlaps a sanitizing rule. Reordering rules cannot create an exception.

    Keep mappings across restarts¶

    Use a file vault when a conversation must retain its synthetic mappings across normal proxy restarts. The key and encrypted mapping file are both local.

    persistent-vault.yaml — complete file
    # Complete configuration. Save hosts.txt beside this file.
# Keep both vault files private and together; only one proxy may use this vault.
listen: localhost:8787
ui:
  listen: localhost:8788
upstreams:
  codex: https://chatgpt.com/backend-api/codex
policy:
  profile: sanitize
  on_error: block
  unsupported: block
vault:
  mode: file
  key_file: .state/vault.key
  file: .state/vault.bin
audit:
  enabled: true
  file: .state/persistent-decisions.jsonl
  on_error: block
rules:
  - name: builtin
    type: builtin
  - name: service-hosts
    type: dictionary
    file: hosts.txt
    synth: hostname
  - name: aws-keys
    type: regex
    pattern: '\b(?:AKIA|ASIA)[0-9A-Z]{16}\b'
    synth: secret
  - name: ticket-ids
    type: regex
    pattern: '\bDEMO-[0-9]{6}\b'
    synth: secret

    The proxy creates missing state directories/files with private permissions. Keep the key and vault together in your private backup process; someone with both can recover the mappings. Only one proxy may use this vault at a time. Writes are periodic and on clean shutdown, so an abrupt crash can lose recent mappings. Do not delete or rotate the key while expecting old mappings to work.

    test-rules still uses a throwaway vault even when given this configuration. It does not inspect or change the production file vault.

    Adapt a recipe for your environment¶

    Need Change Check
    More hostnames Add literal lines to hosts.txt Positive and near-miss string tests, then reload
    Usernames, paths or project names Add a separate dictionary rule with synth: secret Built-ins do not cover arbitrary names/paths
    Your own identifier format Add a Go regex with a suitable synth Whole match is replaced; rule anatomy
    Different API/backend Change upstream and corresponding Codex authentication Restart; Codex setup
    A second isolated policy Separate YAML, ports, audit file and file vault Point that client at the correct local URL
    Larger request bodies Edit policy.max_body_bytes Does not raise fixed metadata/argument-stream limits

    There is no per-value allowlist, built-in-category selector, per-request bypass, or automatic per-repository policy selection. A dictionary entry is a detection rule, not an approved destination. See supported overrides before trying to narrow a rule.
