    Codex protocol support and semantic evidence¶

    This matrix describes the repository adapter, not every version of Codex or the Responses API. It qualifies representation and local effects. A model can reason differently about synthetic values, even when every round trip is lossless.

    Tests below live in internal/adapter/codex/ unless another package is named. Run go test ./internal/adapter/codex ./internal/proxy ./internal/sse with output captured as described in verification. The deterministic HTTP workflow corpus in scripts/workflow/ remains the end-to-end boundary check.

    Form Behavior and diagnostic Executable evidence
    POST /v1/responses, JSON request, uncompressed SSE response Sanitizes request and restores supported response fields TestMatch, proxy workflow suite
    GET /v1/models without a body Passthrough, not content sanitization TestMatch, proxy TestPassthroughRouteWithBodyBlocked
    Other paths/methods, including separate compact/retrieve/resume routes Unsupported route; no automatic translation proxy TestUnknownRouteBlocked

    Effects and limits¶

    TestSemanticsCommandEffects sends arguments through sanitization and chunked argument restoration, executes a fixed local shell command, and checks resulting file bytes and parsed configuration values. It covers quotes, backslashes, Unicode, integers beyond floating-point precision, decimals and exponents. TestSemanticsPatchEffects applies a restored custom-tool diff to an isolated file and checks its resulting content. Neither executes model-generated code.

    These are bounded representative contracts, not proof of all shell languages, patch dialects, encrypted compaction meaning, client versions or model reasoning. Task 04 performance qualification remains unsuccessful; semantic test success does not change those performance findings.

    Paired live corpus (optional, currently unmeasured)¶

    Use five small cases: argv, file_edit, config_edit, relationship, and tokenization. The first three use the same independent effects as the tests. For relationship, ask the model to compare two fabricated ordered values and check against the original ordering. For tokenization, ask it to count or extract literal characters and check against the original text. These last two expose changes that a reversible value mapping cannot prevent.

    For each case, repeat at least five paired trials using the same model revision, settings, task, oracle and comparable initial state. Alternate direct/proxy order; keep each trial independent. Preserve prompts and detailed evidence privately. Record every attempted arm, including failures; never drop a failed pair. Classify transport/policy/restoration failures separately from a successfully delivered answer that fails the task oracle. A provider error on either arm is a provider failure; a proxy failure is possible only on the proxy arm. Missing-arm records are invalid, not successful evidence. Review classification against private logs.

    The offline scripts/workflow/live_semantics.py accepts a JSON object with schema_version: 1 and a records list. Each record has exactly:

    • pair_id: short stable identifier, unique per trial (repeated for its two arms).
    • case: one of the five case names above.
    • model: exact model revision identifier, equal within each pair.
    • arm: direct or proxy.
    • status: ok, provider_failure, or proxy_failure.
    • semantic_pass: boolean for ok, otherwise JSON null.

    It performs no network calls. Run it against the private outcome file with stdout and stderr captured. Its output contains aggregate counts and fixed case names only. It reports all pairs, comparable pairs, both-pass/both-fail, discordant outcomes, failure-arm counts and pairs with failures. Failure-arm counts can exceed failed-pair counts. Empty input is explicitly unmeasured. Nonempty input means observations exist, not that the corpus is complete or qualification passed.

    Discordance measures observed outcome differences; it does not attribute them causally to the proxy. Model sampling variance requires repeated trials, matched settings and review of raw evidence. No live trials were run for this change, and no model-quality or statistical equivalence claim is made.
